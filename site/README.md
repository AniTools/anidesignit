# AniDesignIt

The AniDesignIt portfolio, built in [Astro](https://astro.build) with
[Keystatic](https://keystatic.com) as the CMS. Ported from the Claude Design
canvas files in the parent folder (`AniDesignIt Landing.dc.html`,
`AniDesignIt Case Study.dc.html`), which stay where they are as the design
source of truth.

## Running it

```bash
npm install
npm run dev
```

- Site — <http://localhost:4321>
- CMS — <http://localhost:4321/keystatic>

| Command | What it does |
| --- | --- |
| `npm run dev` | Dev server **and** the CMS |
| `npm run build` | Static site into `dist/` — no CMS, no server |
| `npm run preview` | Serve the built `dist/` locally |

## Editing content

Everything on the site is editable at `/keystatic` — no code, no account, no
subscription. Three areas:

- **Projects** — the six case studies. Name, year, role, client, subtitle,
  summary, tools, cover image, gallery, live link, extra links, key lesson,
  testimonial, and the case study body in a rich-text editor. `Order` controls
  the sequence in My Work; lower numbers come first. The URL slug is the address
  of the case study, so changing it changes the link.

  The body uses **Heading 2 for each chapter** — the coral 01 / 02 / 03 numbers
  are generated by CSS, so write "The Problem", never "01 The Problem", and the
  numbering stays right when you add or reorder sections. Heading 3 and 4 are
  sub-sections inside a chapter.

  **Images go in the body**, dropped wherever they belong in the story, the same
  way the old site read — not in a gallery at the end. Add them with the image
  button in the editor toolbar. They are optimised at build time like every
  other image, and click to open full size.
- **Services** — the six-up grid on the Services section.
- **Site copy & contact** — your name, hero and about copy, email, phone,
  booking link, social links, and the three Lottie URLs.

Keystatic writes plain JSON into `src/content/`. Save in the CMS, and the dev
server reloads immediately. Deploying is what publishes the change.

Images accept **either** an existing URL **or** a direct upload, chosen per
image. All 30 case study images have been migrated off Firebase Storage to
local uploads — the site has no remaining runtime dependency on Firebase.
Uploads land in `public/images/projects/`.

### Publishing your changes

Keystatic runs in `local` mode — it edits files on this machine, so the CMS
only exists while `npm run dev` is running. Editing in the CMS updates your
local copy of the site instantly, but **does not touch the live site** until
you publish.

Publishing means committing and pushing to GitHub, which triggers Netlify to
rebuild automatically. The easiest way:

```bash
./publish.sh                      # commits everything with today's date
./publish.sh "Added new project"  # or write your own message
```

Run it from the project root after saving in Keystatic. It stages every
change, commits, and pushes in one step — nothing to remember beyond running
the script.

### Editing from any browser

Right now the CMS only runs locally (`npm run dev` → `/keystatic`), so editing
means: run the dev server on this machine, make changes, then `./publish.sh`.
To edit from any browser without running anything locally, Keystatic would
need to move to GitHub-backed storage (edits become commits directly from the
browser) and the CMS would need to run on the live site rather than only in
dev. That's a bigger, separate change — ask if you want it set up.

## Deploying

The repo (`github.com/AniTools/anidesignit`) is connected to Netlify
(`anidesignit.netlify.app`) — every push to `main` triggers an automatic
rebuild and deploy. `netlify.toml` sets the build: base `site`, command
`npm run build`, publish `dist`.

The live domain `anidesignit.com` is still pointed at the old Firebase-hosted
site — this Netlify site is a staging/preview deploy until the domain is
migrated over.

The contact form uses **Netlify Forms** — no backend, no third-party service,
100 submissions a month on the free plan. It only works once deployed to
Netlify; locally the submission fails and the form shows its error state, which
is expected. Submissions arrive under **Forms** in the Netlify dashboard.

To host somewhere else instead, drop `netlify.toml`, remove `data-netlify` and
the `form-name` hidden input from the form in `src/pages/index.astro`, and point
the form at a service like Formspree.

## How it is put together

```
src/
  content/          Content as JSON — what the CMS writes
    projects/       One file per case study
    services/       One file per service
    site/copy.json  Global copy, contact details, social links
  content.config.ts Schemas that validate the above at build time
  styles/tokens/    Design tokens, copied verbatim from ../_ds
  components/       The _ds design system, ported to .astro
  layouts/Base.astro
  pages/
    index.astro     The five-section landing page
    work/[slug].astro  Case study template, one page per project
```

**Design tokens** in `src/styles/tokens/` are copied from the `_ds` design
system in the parent folder. Treat `_ds` as the source: change tokens there and
re-copy, rather than letting the two drift apart.

**The landing page** is one page with five sections on a horizontal track.
Desktop moves the track with `transform`; under 768px the CSS unwinds it into a
normal vertical scroll and the JS controller stands down. Wheel, arrow keys, the
dots, and the nav links all drive it.

**Images** go through Astro's build-time pipeline via `SmartImage.astro` —
the source covers run 3.6-10MB, and come out as WebP srcsets of 20-290KB. If a
remote host cannot be reached at build time the component falls back to the
original URL rather than failing the deploy, and logs which image it skipped.

**Lottie** players load only when scrolled into view, and are replaced by a
static brand mark under `prefers-reduced-motion`.

## Ported but not yet wired up

Three design-system components are ported and ready but nothing references them
yet, so they will not show up until you use them:

- `ProjectCard.astro` — the cover-image work card. The design canvas offers five
  My Work layouts and this site ships the default one, *Editorial split*. This
  is what the *Card grid* and *Film strip* layouts are built from.
- `Testimonial.astro` — the design system's quote treatment. The case study page
  uses the blush pull-quote block from the case study design instead.
- `ProjectNav.astro` — the design system's prev/next. The case study page uses
  the two-card version from the case study design instead.

Delete them if you would rather not carry them.

## Things to know

- **Content came from the live anidesignit.com**, imported verbatim — typos
  included, because it is your published copy and not mine to rewrite. Worth
  fixing in the CMS when you get a moment:
  - The Mod Squad Team → Year reads `Apirl 2026`
  - ZOLU the App → a chapter heading reads `The Chanllange`
  - Louise Lee Website → "I turned the bussy landing page"
- **Two gallery screenshots were far too large to process** — Louise Lee's was
  9073x32768 (67MB) and Marquess's 5760x25996 (30MB); both were being served at
  full size on the old site. They are pre-shrunk into `public/images/projects/`
  as WebP (663KB and 781KB). If you replace them, export nearer 1600px wide.
- **Cover images are still large** — The Mod Squad's is 10MB. The build handles
  it, but exporting nearer 2000px wide would make builds much faster.
- Node 20 or newer.
